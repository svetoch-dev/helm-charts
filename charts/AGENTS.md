# Helm chart rules

- Start with the chart's `Chart.yaml`, `values.yaml`, templates and README where present. Reuse the nearest chart or helper. Keep shared operators and resources separately selectable, as in [`postgres`](postgres/) and [`redis`](redis/). [`gha-runner`](gha-runner/) and [`vedro`](vedro/) show composition with pinned upstream charts. Load [workload and helper rules](chart_deps/app/AGENTS.md) when changing `common` or `core`. For domain helpers, see the [Prometheus](chart_deps/prometheus/lib/) and [Fluent Bit](chart_deps/fluent/fluentbit/lib/) libraries.
- Preserve values keys, resource names, labels and selectors. When missing differs from explicit `false`, zero or empty, check key presence and render both cases. Keep supported `tpl` contexts and namespaced helpers. Copy shared maps before mutation. Do not use `dig`. Follow the chart's existing ingress interface.
- Pin versions in first-party dependency declarations. Match optional dependency conditions to Boolean keys under the alias or dependency name. Follow actual `file://` paths through consumers. Rebuild affected tracked packages from the inner dependency outward with `helm dependency build` for an existing lock or `helm dependency update` to change resolution. Check locks, `.gitignore`, and `git ls-files`. Leave ignored packages out. See [dependency rebuilds](../UPGRADING.md#5-rebuild-local-dependencies).
- Preserve Application finalizers and pruning settings in unrelated work. Check removal impact before disabling or renaming an Argo CD Application.
- Render with neutral inputs from the chart's README, defaults, or consumer input schema. Check expected resources, identities, duplicate keys, and enablement. Render representative consumers when changing a shared dependency.
